# 文章产出质量约束规范 v1

> 目的：把用户历史抱怨（14 条原始记录）转化为可执行的产出约束，解决
> "deepseek-v4-flash 写出来质量差"的问题——质量靠约束产出，不靠换模型。
> 使用：本规范随选题一起发给产线 worker，作为 draft 阶段的强制要求。

## C1. 深度：一篇一个核心观点，讲透

- 每篇文章只解决一个问题，一个核心论点贯穿全文
- 禁止"面面俱到"的综述感——那是"单薄"的根源（把 5 个点各写 2 句，不如 1 个点写透）
- 技术文章必须有：真实案例/数据/代码/复现路径，至少两项
- 禁止用"在当今 AI 时代""随着技术发展"这类空话填充字数

## C2. 文体：是文章，不是说明文档

- 有叙事弧线：钩子（开头 3 行内）→ 展开 → 反转/洞察 → 收尾
- 第一人称"我"，有观点、有态度、有判断（"我认为这值得警惕"而非"值得注意的是"）
- 禁止产品说明书腔：不要"本工具支持 X、Y、Z 功能"这种罗列
- 读者读完要有"哇，还能这样"或"原来如此"的收获感，不是"看完了"的平淡

## C3. 去 AI 味（humanizer 34 条的核心，前置到 draft 阶段）

- 禁词：值得注意的是、此外、总而言之、至关重要、在当今时代、综上所述、
  随着…的发展、为…奠定了基础、不仅…而且（滥用时）、赋能、抓手、闭环（非技术语境）
- 禁句式：每段都以"这"开头、排比三段式、反问句连环、"让我们"祈使句
- 禁结构：教科书式"定义-分类-举例"、章节编号 01/02、"挑战与展望"模板
- 禁 emoji 标题（🚀💡✅）、禁📌元数据框（"这篇文章聊什么""预计阅读"）
- 人味测试：把文章读出声，如果有人这么跟你说话你会觉得奇怪，就重写

## C4. 标题：钩子+具体事实，数字优先

- 格式：具体数字/事实 + 反差/悬念/判断
- 好例：`LLM Heist：劫持 LiteLLM 网关，偷走流量、密钥和工具调用`
- 坏例：`AI 安全的重要性与挑战`（教科书）、`AI Agent 安全深度解析`（空泛）
- 禁"实测报告"、"最后得罪人"式结尾、标题党（夸大但无内容支撑）

## C5. 长度：按赛道定，禁止一刀切

- 赛道 A（攻防实战）：800-1500 字，故事密度高，阅读快
- 赛道 B（EDR 对抗）：1500-3000 字，允许长文，深度优先
- 赛道 C（Agent 治理）：1000-2000 字，数据驱动，CISO 视角
- **翻译类豁免字数上限**（2026-08-09 用户确认）：翻译文章忠实原文优先，
  原文多长就译多长，不卡 C5 字数（C10 第 1 条忠实原文 > C5 字数）。
  译文可超 1500/3000 字，前提是章节一一对应、无注水段——QA Gate 核对
  "无注水"即可。原创类仍按 C5 执行。

## C6. 事实准确：可核验优先

- 所有数据/引用必须有来源（链接/报告名），无法核验的明确标注
- 技术细节（命令、API、版本号）必须与素材一致，不臆造
- 涉及漏洞/攻击手法：说明适用范围（授权测试），不写无脑攻击教程

## C7. 封面与重复

- 每篇必须生成封面（900×383），样式与历史文章可区分
- **多风格**（2026-08-09 升级）：generate_cover.py v3 支持 5 种风格
  （blue 攻防 / dark EDR / clean 治理 / red 变现 / violet 翻译研究），
  按选题赛道选（auto_style 自动判定），连续两篇禁止同风格——
  公众号主页大量同风格封面 = 无区分度（用户反馈）
- **封面内容个性化**（2026-08-10 升级，v4）：仅风格不同不够——同风格两篇的装饰
  必须随文章内容不同。generate_cover.py v4 增加标题关键词驱动的主题装饰层：
  hex 字节流=逆向/二进制/注册表、管道流量线=网关/劫持/拦截/注入、
  拓扑节点=Agent/蜂群/协作/多、点阵网格=内核/EDR/Rootkit/漏洞。
  同风格的两篇封面视觉必须可区分（用户反馈：UCPD 与 Cursor 同为 violet 风格、
  装饰相同被指"封面一样"——hex 流 vs 拓扑节点即可区分）
- 徽章 = 赛道（A 攻防实战 / B EDR 对抗 / C Agent 治理 / D 变现向 / 翻译）
- 同一标题/高度相似标题禁止重复发布——发稿前查历史标题

## C8. 排版（微信最终渲染）

- 代码块：``` 围栏（不能用缩进），`white-space: pre` 确保移动端不换行错乱
- 公式单独占行，前后留空行，不混在正文
- 正文字号统一（14-16px），标题层级清晰（h1 标题/h2 小节），不堆砌加粗
- CSS 纯标签选择器（body/p/h1/h2/pre 等），**禁止 .wechat-article 类选择器**
- `<style>` 写在 YAML frontmatter 之后、正文之前（编辑器会吞 style，见历史教训）
- 微信草稿箱会静默删 `<style>`——必须 premailer CSS 内联后再推送
  （wechat_push.py 已固化；**禁用 pygments 语法高亮**——彩色 span 在微信渲染
  错乱、代码内 `***` 会被当 markdown 加粗，2026-08-09 已修复，
  代码块用统一 <pre> 样式）

## C9. 格式一致性（防回退）

- 每次产文必须对照最近一篇已发布文章的格式（07/08 系列），禁止"回到最开始没有格式的样子"
- **CSS 必须用 14px 新模板**（2026-08-09 固化）：body 14px / PingFang SC 字体栈 /
  h1 24px / h2 18px 蓝左边框 / h3 16px / 代码块深底 #1e293b / 内联代码浅蓝底——
  与 LLM Heist、SakDriver 一致。**禁止旧模板**（17px、-apple-system 字体栈、em 相对字号）
- 产出后跑 wechat-preview.html 目检：字体、代码块、图片、段落节奏四项
- 格式模板以 projects/wechat-publisher/assets/wechat-article.css 为准

## C10. 翻译类文章（海外技术研究翻译专用，2026-08-09 新增）

> 触发：选题为英文一手技术研究（wunderwuzzi23、Fir3n0x、OWASP、NVIDIA AI Red Team 等），
> 产线按"翻译整理"处理，不是原创改写。参考样板：GAP 译文（marketing/evidence/style-refs-2026-08-09/ref3-gap-persistence.md）。

- **忠实原文**：内容与原文一致，章节一一对应，不增删主体内容、不夹带译者的观点扩展
- **结构跟随**：译文标题结构完全跟随原文（引子→前置→组件→攻击链→价值→披露→PoC），
  原文有 section 就保留 section，不自行重排
- **术语处理**：技术名词保留英文（Secure Preferences、ScriptCache、version_id），
  首次出现给中文说明（GAP=幽灵锚点持久化）；标题可中英结合（"GAP — 幽灵锚点持久化"）
- **禁机械直译**（2026-08-09 用户修正）：英文词组必须用标准译法，禁止字面硬翻——
  反例：canned response→"罐头响应"（错，应为"预制响应"）；拿不准时查词典/标准译法
- **第一人称统一译作"作者"**（2026-08-09 用户定案）：原文 I 一律译"作者"
  （"作者在攻击者网关上装了 auth hook"），不写"本文译自 XXX 第一人称均为原作者"之类的
  视角说明段；原文 we 用无主语句式（"研究假设""劫持管线成立"）；读者自然理解视角归属
- **长段拆短**：原文大段落拆成"短段 + 关键概念单独成行/加粗"——这是"内容整理方式"的核心：
  原文 5 行一段 → 拆成 2-3 个短段，关键结论独立成行加粗
- **路径/命令代码化**：文件路径、API 名、缓存键、命令必须用代码块包裹
- **列表化**：原文 bullet/编号列表转中文列表，保持条目完整（红队价值 6 条就是 6 条）
- **图表保留**：原文 ASCII 架构图/表格原样保留（可转代码块或 markdown 表格）
- **免责声明保留**：原文文末的教育/研究声明必须翻译保留
- **来源标注**：frontmatter source 字段写原文 URL + 作者 + 发布日期（如 GAP 样板）
- **原创与翻译分流**：翻译类不适用 C1 的"原创核心观点"要求（观点是作者的），
  不卡 C5 字数上限（忠实原文优先，见 C5 豁免），
  但适用 C2（是文章不是说明书）、C3（去 AI 味——翻译腔也是 AI 味）、C4/C6/C8/C9

## 使用方式

1. 选题确认后，把对应赛道的约束编号（A→C1,C2,C3,C4,C5,C6；B→C1,C2,C3,C4,C5,C6；
   C→C1,C2,C3,C4,C5,C6,C7；翻译类→C2,C3,C4,C6,C8,C9,C10）拼进产线 request 的 message
2. humanizer 阶段仍跑 34 条检查（约束前置后，humanizer 作为第二道）
3. QA Gate 1-4 核对约束逐项过
