### 2.2 各平台详细内容适配方案

#### 2.2.1 微信公众号（主阵地/首发平台）

**定位**：品牌旗舰店，完整课程体系的入口，建立权威感

**内容形式**：

| 内容类型 | 详细做法 | 适用阶段 |
|----------|----------|----------|
| **阶段导读文** | 每个 Phase 发布一篇 3000-5000 字深度导读，给出该阶段的知识地图和进入门槛 | Phase 0-19（共20篇） |
| **单课精讲** | 选取每阶段最具代表性的 3-5 节课，展开为 2000-3000 字中文文章。保留 MOTTO → PROBLEM → CONCEPT 结构，BUILD IT 部分用代码截图+注释标注呈现 | 全部阶段精选 |
| **"动手做"系列** | 将 code/ 中的实现步骤化，配合代码高亮截图（Carbon 风格），引导读者跟着做 | Phase 1-7, 10-14 |
| **工具速递** | 每篇文章末尾附「本课工具箱」：对应的 Prompt 模板、Skill 文件下载/获取方式 | 全部 |
| **路线图/汇总** | 每周一篇汇总推文，用 mermaid 图（转 PNG）展示学习进度 | 持续 |
| **读者作业展示** | 收集读者提交的代码和感悟，精选展示 | 持续 |

**排版规范**：
- 代码块用 Carbon.sh 生成截图（深色背景，Monaco 字体，圆角阴影）
- 关键概念用信息图卡片呈现
- Mermaid 流程图转 SVG → PNG，嵌入文中
- 每篇文末固定引导块：关注公众号 → 加交流群 → 访问官网

#### 2.2.2 知乎

**定位**：搜索引擎入口，长尾流量持续收割

**内容形式**：

| 内容类型 | 详细做法 |
|----------|----------|
| **专栏文章** | 将公众号精讲文章同步到知乎专栏，全文发布（不做摘要引流），利于百度/Google 索引 |
| **深度问答** | 针对高搜索量问题撰写答案，内嵌课程相关章节：如「如何从零实现一个 Transformer？」→ 链接到 Phase 7 |
| **想法/碎片** | 每日 1-2 条技术碎片：一个关键代码片段 + 一句话解释，带话题标签 |
| **圆桌/直播** | 每月一次知乎直播：代码 live coding 或答疑，预告 B 站同步 |
| **电子书/付费咨询** | 将精选内容打包为知乎盐选电子书，开设付费咨询（AI 学习路线规划） |

**发布策略**：
- 专栏文章：比公众号晚 24 小时发布
- 问答：即时响应，不犹豫
- 避免被判定为引流号：每篇文章至少有 80% 独立内容价值

#### 2.2.3 B站（Bilibili）

**定位**：视频化课程体验，吸引年轻学习者

**内容形式**：

| 内容类型 | 时长 | 详细做法 |
|----------|------|----------|
| **代码走读视频** | 15-25 分钟 | 屏幕录制 VS Code，逐行讲解一个 lesson 的 code/ 核心实现。左侧 VS Code，右侧终端运行结果 |
| **"从零实现"系列** | 30-60 分钟 | 完整走完一个 Build 类型 lesson：从空文件到可运行，不剪辑或少剪辑 |
| **概念讲解动画** | 3-8 分钟 | 用 Manim 或 Keynote 动画讲解核心概念（如 Backpropagation、Attention、Agent Loop） |
| **工具评测/对比** | 5-10 分钟 | 对比 PyTorch vs JAX、LangGraph vs CrewAI 等，引用 Phase 相关课程 |
| **学习 Vlog** | 5-15 分钟 | "我用 30 天学完了 Phase 14 Agent Engineering"类记录视频 |
| **直播 Coding** | 60-120 分钟 | 每周一次直播 coding，现场写代码+答疑 |

**视频制作规范**：
- 统一片头（3 秒 Logo 动画）+ 片尾（关注公众号 + 知乎专栏 + 官网）
- 代码录屏用 VS Code + Monokai Pro 主题，字号 16+
- 关键步骤叠加文字标注
- 视频简介区放：时间戳、代码 GitHub 链接（原始仓库 + 中文解读仓库）、公众号、知乎专栏、交流群
- 用飞书/妙记自动生成字幕

#### 2.2.4 CSDN

**定位**：SEO 长尾收割，资源下载引流

**内容形式**：

| 内容类型 | 详细做法 |
|----------|----------|
| **完整教程** | 知乎/公众号文章的全文同步，代码块直接贴文本（不截图），便于搜索和复制 |
| **资源下载帖** | 打包 outputs/ 中的 prompt 和 skill 文件，提供下载链接（需关注公众号获取） |
| **环境搭建帖** | Phase 0 的 12 节课天然适合单独成帖：「AI 开发环境搭建」「GPU 云端配置」等 |
| **问答帖** | 针对 CSDN 问答区的高频问题写解答，嵌入课程相关章节 |
| **连载目录帖** | 维护一个索引目录帖，汇总所有 CSDN 发布链接 |

**SEO 优化**：
- 标题包含核心关键词：「从零实现」「手把手」「保姆级」「AI 教程」
- 文章前 200 字包含目标关键词
- 图片 ALT 标签填中文描述
- 文末引导关注公众号获取「完整 503 节课程路线图」

#### 2.2.5 掘金

**定位**：高质量技术社区传播，建立个人品牌

**内容形式**：

| 内容类型 | 详细做法 |
|----------|----------|
| **技术深度文章** | 选取最具技术深度的课程（如 Phase 7 Transformers、Phase 10 LLMs from Scratch），写成掘金风格的技术博文 |
| **工具推荐/评测** | 每节课产出的 Skill/Prompt/MCP Server 写成工具推荐文章 |
| **实战 Demo** | 用 Phase 19 的 Capstone Projects 写出完整 Demo 文章：「用 200 行 Python 写一个 Coding Agent」 |
| **沸点** | 每日碎片化分享：一个代码片段、一个概念理解、一个学习心得 |

**掘金特色**：
- 注重代码完整性和可复现性
- 开头用 TL;DR 摘要（掘金读者偏好）
- 多用掘金的「代码块」功能贴完整代码
- 参与掘金征文活动蹭流量

#### 2.2.6 小红书（RED）

**定位**：碎片化知识传播，泛用户破圈

**内容形式**：

| 内容类型 | 详细做法 |
|----------|----------|
| **知识卡片** | 每节课核心概念做成 1-9 张精美卡片：1 张封面 + 最多 8 张知识点 |
| **学习路线图** | 20 个 Phase 的学习路线可视化，标记难度和学时 |
| **代码片段卡片** | 一屏内的 Python 代码 + 输出结果，做成竖版卡片（Carbon 风格） |
| **工具清单** | 「AI 工程师必备的 10 个 Prompt」「5 个 Skill 让你的 Coding Agent 起飞」 |
| **"一张图搞懂"系列** | Attention 机制、Agent Loop、MCP 协议等复杂概念的单图解释 |
| **学习打卡** | 「Day 1/30：今天学了线性代数直觉」，配合学习笔记照片 |

**小红书设计规范**：
- 统一视觉模板：3:4 竖版尺寸（1080×1440px）
- 配色方案：深色背景为主（契合 AI/代码主题），品牌蓝 #3553FF + 白色文字
- 使用 Canva/Figma 模板批量生产
- 每篇正文放完整学习路线引导

### 5.3 一次生产，六平台分发的 SOP

```
Step 1：选定 1 节课，阅读 docs/en.md + code/ + outputs/
        ↓
Step 2：撰写「公众号精讲稿」（中文，3K字，含代码截图、概念卡片、工具附送）
        ↓（工时：2-3h）
        
Step 3：从精讲稿派生：
        ├── 知乎专栏版：精讲稿精简至 2K字，增强问答属性，加相关话题标签
        ├── CSDN 版：精讲稿 + 原文代码块（文本格式）+ SEO 标题优化
        ├── 掘金版：精讲稿 + TL;DR + 掘金代码块 + Demo 演示
        └── 小红书卡片版：从精讲稿提取 6-9 个核心知识点 → Canva 模板生成卡片
        ↓（工时：1-2h）
        
Step 4：基于精讲稿写视频脚本
        ├── B站长视频（15-25min）：脚本 + 屏幕录制 + 配音/字幕
        └── 小红书/抖音短视频（1-3min）：拆解 1 个核心概念
        ↓（工时：2-4h，含录制剪辑）

Step 5：按照发布日历，依次在各平台发布
        公众号(首发) → CSDN(同步) → 知乎(次日上午) → 掘金(次日中午) 
        → B站(次日晚) → 小红书(次日晚)

总工时预估：1 节课完整六平台分发需 6-10 小时（单人）
```

## 六、发布工具与 API 评估

### 6.1 各平台官方发布能力

| 平台 | 官方工具 | API 能力 | 限制 |
|------|----------|----------|------|
| **微信公众号** | 后台编辑器 / 订阅号助手 App | ❌ 无公开 API（仅企业号有部分 API） | 每天 1 次群发（订阅号）；草稿箱无限制 |
| **知乎** | Web 编辑器 / App | ❌ 无公开 API（封杀第三方） | 无日发文限制；需注意反爬 |

| **CSDN** | Web 编辑器 / App | ✅ 有开放平台 API（需申请） | Markdown 编辑器支持良好 |
| **掘金** | Web 编辑器 / App | ❌ 无公开 API | 需手动发布；有审核机制 |
| **小红书** | App 发布为主 / 小红书创作服务平台（Web） | ❌ 无公开 API，反爬极严 | 强烈依赖 App；Web 端功能受限 |

## 九、风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| 微信公众号封号（AI 内容敏感） | 毁灭性 | 遵守平台规范；避免绝对化用语；提前备份粉丝到微信群 |
| 原创度不足被平台判定搬运 | 限流/降权 | 每平台内容至少有 30% 差异化改写；优先保证原创首发 |
| 多平台维护精力不足 | 质量下降 | 初期集中 3-4 个平台（公众号+知乎+B站+CSDN）；后期逐步扩展 |
| 英文课程中译质量参差 | 专业度受损 | 用 AI 初译 + 人工精校；建立术语表（glossary）保持一致 |
| B站视频制作效率低 | 产出跟不上 | 降低剪辑投入，走"录屏+配音"极简路线；后期再升级制作 |
| 平台算法变化 | 流量波动 | 多平台分摊风险；公众号私域是最稳底盘 |
