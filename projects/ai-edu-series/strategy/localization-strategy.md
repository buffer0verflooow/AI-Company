## 二、本地化核心策略：并非简单翻译，而是"文化转译"

### 2.1 总体原则

| 原则 | 说明 |
|------|------|
| **学术术语保留英文缩写 + 中文全称** | 如"Transformer（变换器）"首次出现时标注，后续直接用英文 |
| **数学公式保留原始符号** | 变量名、公式结构不改——这是全球统一的数学语言 |
| **概念解释全中文化** | 用中文重新讲述直觉、类比和应用场景 |
| **代码保留英文** | 类名、变量名、函数名保留英文，新增中文注释 |
| **比喻和案例全面替换** | 将西方文化语境替换为中国读者熟悉的比喻 |

### 2.2 哪些概念/比喻需要替换

#### 2.2.1 文化比喻替换表

| 原文（英文语境） | 本地化替换（中文语境） | 适用场景 |
|---|---|---|
| "Building a house from bricks"（砖块盖房） | "搭积木" / "搭乐高"（中国读者更熟悉的隐喻） | 模块化概念、组件拼接 |
| "Peeling an onion"（剥洋葱） | "剥竹笋" 或 "拆俄罗斯套娃"（中国读者更能共鸣） | 层层递进的抽象概念 |
| "Recipe"（食谱） | "菜谱" → 替换为中国菜式，如"做红烧肉"替代"烤牛排" | Pipeline / 流程讲解 |
| "Baseball batting average"（棒球击球率） | "考试及格率" 或 "篮球命中率" | 模型准确率评估 |
| "Hockey stick growth"（曲棍球棒增长） | "指数级增长" / "J 型曲线" | 技术发展趋势 |
| "Swiss army knife"（瑞士军刀） | "瑞士军刀"可保留（中国认知度高），补充"万能工具箱" | 多功能工具比喻 |
| "Sherlock Holmes"（福尔摩斯） | "狄仁杰" 或 "包青天" | Agent 推理/查案比喻 |
| "Cowboy coding"（牛仔编程） | "野路子编程" / "裸奔式开发" | 不规范开发方式 |
| "The Wild West"（狂野西部） | "草莽时代" / "野蛮生长" | 技术早期阶段 |
| "Garbage in, garbage out" | "种瓜得瓜，种豆得豆" / "歪瓜裂枣进，歪瓜裂枣出" | 数据质量 |
| "Walking before running" | "还没学会走就想跑"（恰好在中文中是相同表达） | 循序渐进学习 |
| "Boiling the ocean"（把海烧开） | "大海捞针" / "好高骛远" | 不切实际的目标 |

#### 2.2.2 概念理解难点（中文读者特有）

| 英文概念 | 中国读者的认知挑战 | 本地化策略 |
|---|---|---|
| **Embedding（嵌入）** | 直接音译"嵌入"不够直观 | 补充说明："把词/图变成一串数字，相似的东西数字也相似，相当于给每个词分配了一个 768 维的'身份证号码'" |
| **Attention（注意力）** | 翻译为"注意力"但实际含义更接近"关注度" | 用"相亲打分表"比喻：每个词都在给其他词打分，分高的多关注 |
| **Backpropagation（反向传播）** | "传播"这个词在中文里不够直观 | 用"传话游戏纠错"比喻：从最后一棒往前传，每个人根据结果调整自己 |
| **Token（令牌/词元）** | "令牌"太生硬，"词元"太学术 | 用"最小文本单位"并举例："hello" → 1 个 token，"你好" → 2 个 token |
| **Gradient（梯度）** | 纯粹的数学概念，非数学背景读者困惑 | 用"山坡坡度"比喻：梯度就是告诉你往哪个方向走下山最快 |
| **Latent Space（潜在空间）** | 过于抽象 | 用"压缩包"比喻：把一张 4K 照片压成 100 个数字，这 100 个数字就是 latent space 里的一个点 |

#### 2.2.3 可保留的全球通用概念

以下概念在中英文中认知一致，无需替换：
- 数学符号和公式（$\hat{y} = Wx + b$）
- 常见算法名（ReLU, Sigmoid, Softmax, Adam, SGD）
- 论文引用（"Attention Is All You Need"等）
- 框架名（PyTorch, TensorFlow, JAX, LangChain）
- 编程术语（class, function, loop, if-else）
- 开源文化概念（GitHub, PR, Issue, fork, star）

## 三、代码与数学的本地化规范

### 3.1 代码示例处理

#### 规范：保留英文代码 + 添加中文注释

```
原文（无注释）：
def dot_product(a, b):
    return sum(x * y for x, y in zip(a, b))

本地化后（加中文注释）：
def dot_product(a, b):
    """计算两个向量的点积（内积）。
    
    点积衡量两个向量方向的相似度：
    - 结果 > 0：方向相近
    - 结果 = 0：垂直（无关）
    - 结果 < 0：方向相反
    """
    return sum(x * y for x, y in zip(a, b))  # 逐元素相乘再求和
```

#### 变量命名规则：保持不变
- 类名、函数名、变量名 **保持英文**
- 文档字符串（docstring）**改为中文**
- 关键逻辑行添加 **行内中文注释**
- 输出/打印信息 → **改为中文**

### 3.2 数学公式处理

| 处理方式 | 范围 |
|---|---|
| 保留原样 | 公式本身、变量符号、LaTeX 表达式 |
| 中文化 | 公式前后的解释段落、数学概念的直觉讲解 |
| 增加 | 每个公式增加"白话解读"旁注 |

### 3.3 技术术语对照表（核心示例）

| English | 中文翻译 | 使用规范 |
|---|---|---|
| Neural Network | 神经网络 | 全文中文 |
| Deep Learning | 深度学习 | 全文中文 |
| Transformer | Transformer | 保留英文（首次标注"变换器"） |
| Attention Mechanism | 注意力机制 | 全文中文 |
| Fine-tuning | 微调 | 全文中文（首次标注 Fine-tuning） |
| Prompt Engineering | 提示词工程 | 全文中文（首次标注英文） |
| Reinforcement Learning | 强化学习 | 全文中文 |
| Embedding | 嵌入向量 / 词向量 | 具体场景选择 |
| Token | Token（词元） | 保留英文为主 |
| Inference | 推理 / 推断 | 依上下文选择 |
| Agent | 智能体 / Agent | 可混合使用，首次标注对应关系 |

- **内容形式**：精美图文（小红书笔记），每篇 500-1500 字
- **选题方向**：
  - "30 天 AI 入门计划"打卡系列
  - AI 工具实测推荐（国产模型 PK）

## 八、风险与应对

| 风险 | 影响 | 应对策略 |
|---|---|---|
| **翻译质量参差不齐** | 口碑受损 | 建立严格的审校流程（翻译→技术审校→语言润色→终审） |
| **AI 内容监管政策变化** | 内容下架 | 密切关注政策动态，预留合规弹性，避免"越线"内容 |
| **竞品大量出现** | 市场份额被稀释 | 差异化定位：强调"从零构建"的工程实践而非纯理论 |
| **中国读者对英文代码抵触** | 完读率低 | 增加中文注释和讲解，降低语言障碍 |
| **MIT 协议下的版权争议** | 法律风险 | 保留原始版权声明，明确标注改编来源 |
| **不同平台内容调性冲突** | 品牌形象混乱 | 建立严格的品牌规范和内容分级体系 |
