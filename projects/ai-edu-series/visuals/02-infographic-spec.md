## 一、信息图总则

### 1.1 通用规范

| 属性 | 规范 |
|------|------|
| **宽度** | 1080px（公众号最佳宽度，适配 Retina 屏幕） |
| **高度** | 按内容自适应，建议 ≤ 8000px（单张长图） |
| **背景** | `#fafaf5` + 16px 网格点阵图案（`#1a1a1a` @8% 透明度） |
| **主色** | `#3553ff`（品牌蓝）|
| **分区点缀色** | 见封面模板 §2.1（五区段五色） |
| **中文字体** | `Source Han Sans SC` / `思源黑体`（Regular + Bold） |
| **等宽字体** | `JetBrains Mono`（代码、编号、标签） |
| **显示字体** | `VT323`（大号编号，可选） |
| **导出格式** | PNG @2x（2160px 宽）+ 网页用 WebP |
| **文件大小** | ≤ 2MB（公众号图片 10MB 上限，但为保证加载速度建议 ≤ 2MB） |

### 1.2 信息图编号体系

延续源项目的 FIG_编号体系：

```
格式: FIG_[Phase编号].[序号][字母后缀] — [中文描述]
示例: FIG_14.01A — Agent Loop 五要素知识地图
      FIG_14.02B — ReAct 循环代码拆解
      FIG_14.03C — 国产模型 Agent 能力对比表

后缀规则:
  A = 知识地图型
  B = 代码拆解型
  C = 对比表格型
```

### 1.3 通用头部模板

每张信息图顶部统一使用以下头部：

```
┌──────────────────────────────────────────────────────────────┐
│  FIG_XX.0XA — [信息图中文标题]                                │ ← 左上角，11px，JetBrains Mono，#3553ff

│                                                              │
│  ─────────────────────────────────────────────────────────── │
│                                                              │

```

## 二、知识地图型信息图

### 2.1 用途与定位

- **使用频率**: 每 Phase 至少 1 张
- **作用**: 将该 Phase 所有知识点以结构化方式展示，帮助读者建立「全局地图」
- **使用场景**: 放在文章「本篇纲要」部分后面，或作为独立的可分享长图

## 三、代码拆解型信息图

### 3.1 用途与定位

- **使用频率**: 有核心代码实现的 Phase（约 15/20 篇）
- **作用**: 将核心算法/代码逻辑以可视化方式拆解，使读者「一眼看懂」
- **使用场景**: 放在文章「手写实现」部分，作为代码块旁边的配套图

### 3.2 布局结构

代码拆解型采用「代码 → 拆解」左右或上下双栏布局：

#### 标准布局（左右双栏）:

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│   ┌────────────── 代码区 ──────────────┐  ┌── 拆解区 ────┐  │
│   │                                    │  │              │  │
│   │  def run(query, tools):            │  │  ① 主循环入口 │  │
│   │      history = [user(query)]  ─────┼──│  消息缓冲初始化│  │
│   │                                    │  │              │  │
│   │      for step in range(MAX):  ─────┼──│  ② 轮次预算   │  │
│   │          msg = llm(history)   ─────┼──│  模型推理     │  │
│   │                                    │  │              │  │
│   │          if msg.tool_calls:   ─────┼──│  ③ 工具判断   │  │
│   │              for call in           │  │              │  │
│   │               msg.tool_calls:      │  │              │  │
│   │                  result =          │  │              │  │
│   │                  tools[call.name]──┼──│  ④ 工具执行   │  │
│   │                  (**call.args)     │  │              │  │
│   │                                    │  │              │  │
│   │              continue         ─────┼──│  ⑤ 继续循环   │  │
│   │                                    │  │              │  │
│   │          return msg.content   ─────┼──│  ⑥ 返回结果   │  │
│   │                                    │  │              │  │
│   └────────────────────────────────────┘  └──────────────┘  │
│                                                              │
│  ─────────────────────────────────────────────────────────── │
│  左侧：Carbon 风格代码截图（Mac 窗口，语法高亮）               │
│  右侧：对应的拆解注释（圆角标签 + 引导线）                      │
└──────────────────────────────────────────────────────────────┘
```

**设计规则**:
- **代码区**（左侧 55%）:
  - macOS 终端窗口样式（三色按钮 + 标题栏）
  - 背景色：`#1a1a1a` @3% 或全暗底 `#1a1a1a` + `#fafaf5` 文字
  - 语法高亮：关键字 `#3553ff`，字符串 `#00c48c`，注释 `#7a7a78`，函数 `#ffd93d`
  - 字体：JetBrains Mono, 13px, 行高 1.6
  - 行号：灰色 `#7a7a78`，8px，放在左侧 gutter
- **拆解区**（右侧 45%）:
  - 每个拆解点标注编号（① ② ③ ...），圆角标签，14px
  - 标签风格：`#3553ff` 描边 1px + `#3553ff` @8% 填充
  - 引导线：`#3553ff` @30%，1px 虚线（`stroke-dasharray="4 4"`），从标签左边缘连接到代码对应行
  - 拆解说明文字：思源黑体，13px，`#1a1a1a`
  - 额外注释（性能提示/陷阱）：点缀色小标签，放在说明下方

#### 替代布局（上下排列——窄屏适配）:

```
┌──────────────────────────────────────────────────────────────┐
│  ┌────────────────────── 代码区 ────────────────────────────┐│
│  │  def run(query, tools):                                  ││
│  │      history = [user(query)]                             ││
│  │      for step in range(MAX_STEPS):                       ││
│  │          ...                                             ││
│  └──────────────────────────────────────────────────────────┘│
│                                                              │
│  ① 主循环入口 ──→ ② 轮次预算 ──→ ③ 工具判断 ──→ ④ 工具执行   │
│                                                              │
│  ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐           │
│  │①入口│ │②预算│ │③判断│ │④执行│ │⑤循环│ │⑥返回│           │
│  │初始化│ │硬上限│ │工具?│ │验证+│ │继续 │ │结果 │           │
```

### 4.1 用途与定位

- **使用频率**: 约 10/20 篇（框架选型、模型对比、概念辨析等）
- **作用**: 将多个选项/概念放在同一维度下对比，帮助读者快速做出选择
- **使用场景**: 放在文章相关段落旁或作为独立分享卡片
