## 1. 品牌基础

### 1.1 品牌定位一句话

> **「从线性代数到多智能体集群——市面上唯一的、体系完整的、有手写代码的、工程视角的中文 AI 全栈教育内容。」**

### 1.2 品牌调性（5 个关键词）

| 关键词 | 英文 | 含义 |
|--------|------|------|
| **硬核** | Rigorous | 不回避复杂度，数学推导 + 手写代码 + 工程落地。不写「5分钟学会xxx」 |
| **体系化** | Systematic | 20篇完整链路，从数学基础到多智能体集群，脉络清晰可追溯 |
| **可操作** | Actionable | 每篇都能跑、能改、能放进简历。不纸上谈兵 |
| **诚实** | Honest | 不贩卖焦虑，不夸大其词。说清楚什么场景该用什么方案、不该用什么方案 |
| **现代** | Modern | 紧跟2026年前沿——DeepSeek-V3、MCP、MoE、Flash Attention，不是过时教材 |

### 1.3 品牌人格

如果把「AI工程从零开始」比作一个人：

- **身份**: 一线大厂的 AI 架构师转行做教育，写过生产代码，踩过足够的坑。
- **说话方式**: 不说「同学们好」，说「先说一个尴尬的事实」。不卖关子，直接给代码。
- **教学风格**: 「不要 import torch——先自己写一个反向传播。写完了你再用框架，你会知道每一行在干什么。」
- **视觉印象**: 干净、理工感、有秩序——像一个精心维护的 GitHub README 而不是花哨的营销海报。

### 1.4 品牌承诺

> **每篇文章的代码都能在你自己的机器上跑起来。不依赖任何付费 API，不需要任何前置知识——只要你会打开终端。**

### 1.5 品牌口号

- **主口号**: 「从线性代数到多智能体集群，每篇都能跑」
- **副口号**: 「不要调 API，从零手写。不是学会用 AI，而是学会造 AI。」
- **行动口号**: 「Build it. Ship it. 每篇带走一个工具。」

## 2. 配色方案

### 2.1 设计理念

源项目（aiengineeringfromscratch.com）的视觉基因是 **「蓝图蓝 + 工程纸米白」**——灵感来自工程图纸的蓝色线条和略带暖调的工程纸。中文品牌在此基础上做了 **中国化适配**：

- 保留蓝图蓝（#3553ff）作为核心识别色——它已是品牌DNA
- 增加「墨色」层次（从纯黑转向带有温度的黑灰），更适配中文长文阅读
- 引入琥珀色（Amber）作为功能强调色——灵感来自终端警告色和代码注释色
- 为微信公众号（白色背景强约束）提供增强版配色方案

## 3. 字体系统

### 3.1 设计理念

中文技术内容的字体选择有两个强约束：
1. **微信公众号不支持 Web Font**——只能使用系统默认字体
2. **代码块在移动端阅读体验**至关重要——等宽字体必须清晰

因此采用 **「渐进式字体栈」** 策略：优先使用最佳字体，逐级回退到系统默认。

### 3.2 中文字体栈

#### 标题字体（中文）

```css
font-family: "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", 
             "Noto Sans SC", "WenQuanYi Micro Hei", sans-serif;
```

| 平台 | 实际渲染字体 | 字重 |
|------|-------------|------|
| macOS / iOS | PingFang SC Semibold | 600 |
| Windows | Microsoft YaHei Bold | 700 |
| Android | Noto Sans SC Medium | 500 |
| Linux | WenQuanYi Micro Hei | 400 |

> **微信公众号等效设置**: 编辑器中选择「默认字体」+ 「加粗」即可，微信会自动渲染为 PingFang SC / Microsoft YaHei。

#### 正文字体（中文）

```css
font-family: "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", 
             "Noto Sans SC", "WenQuanYi Micro Hei", sans-serif;
```

| 平台 | 实际渲染字体 | 字重 |
|------|-------------|------|
| macOS / iOS | PingFang SC Regular | 400 |
| Windows | Microsoft YaHei Regular | 400 |

- **字号**: 微信公众号 15px-16px，知乎/掘金 16px
- **行高**: 1.8-2.0（中文长文阅读最佳行高）
- **字间距**: 默认（不额外调整）

#### 代码字体（等宽）

```css
font-family: "JetBrains Mono", "Fira Code", "Cascadia Code", "SF Mono",
             "Source Code Pro", "Menlo", "Consolas", "Courier New", monospace;
```

| 平台 | 实际渲染字体 | 备注 |
|------|-------------|------|
| 代码截图（Carbon） | JetBrains Mono | 首选 |
| Web 端 | Fira Code / Cascadia Code | 有连字支持 |
| 微信公众号 | Consolas / Courier New | 微信不支持 Web Font，只能用系统等宽 |
| VS Code / 编辑器 | JetBrains Mono | 推荐读者安装 |

> **微信公众号代码排版技巧**: 使用 [Carbon](https://carbon.now.sh) 生成代码截图（暗色背景 #131830 + JetBrains Mono 14px），读者体验远好于微信原生文本。

### 3.3 英文字体（品牌英文名专用）

品牌英文名 "AI ENGINEERING FROM SCRATCH" 使用：

```css
font-family: "VT323", "Courier New", monospace;
```

- 像素风格等宽字体，致敬源项目的终端美学
- 仅用于 Logo、封面标题中的英文部分、品牌标识
- 不在正文章节标题中使用（使用中文字体栈）

### 3.4 字号体系

| 层级 | 中文字号 | 英文/数字 | 用途 |
|------|---------|----------|------|
| **H1** | 28px Bold | 32px (VT323) | 封面大标题、B站封面 |
| **H2** | 22px Bold | 24px | 文章大标题（公众号） |
| **H3** | 18px Bold | 20px | 章节标题 |
| **H4** | 16px Bold | 17px | 小节标题 |
| **Body** | 15-16px Regular | 15px | 正文 |
| **Caption** | 12-13px Regular | 12px | 图片说明、脚注、日期 |
| **Code** | 13-14px Mono | 13-14px | 代码块、行内代码 |

### 3.5 Mermaid 图表字体

```css
font-family: "PingFang SC", "Microsoft YaHei", sans-serif;
```

- Mermaid 生成 SVG，中文渲染取决于运行环境
- 配色: 黑底蓝线，与源项目风格统一
- 节点文字: 13px，线条文字: 11px

## 4. Logo 设计描述

### 4.1 设计理念

Logo 需同时承载以下品牌信息：
- **工程感**（不是花哨的艺术字，是像蓝图一样精确的几何图形）
- **从零开始**（序列、构建、递进的感觉）
- **AI 主题**（不是具象的机器人，是抽象的「智能结构」）
- **中国味**（一个在中文语境下不突兀、在微信小头像里也能辨认的符号）

### 4.2 方向一：「蓝图方阵」(Blueprint Grid)

**概念**: 一个 3×3 的网格，每个格子是一个逐渐「亮起」的方块——从左下角的灰色（「零」）到右上角的蓝图蓝（「AI工程完成态」）。

**几何构成**:
```
□ □ ■    ← 亮起的方块代表「已构建的知识」
□ ■ ■
■ ■ ■
```

- 9 个圆角方块（半径 2px），间距 2px
- 左下角 3 块 = 蓝图蓝 500（#3553FF）
- 中间 3 块 = 蓝图蓝 400（#6B8EFF）
- 右上角 3 块 = 蓝图蓝 200（#C2CBFF）
- 象征「从零开始，逐步构建完整体系」

**文字组合**: 方块矩阵在左，「AI工程从零开始」在右（PingFang SC Bold, #1A1A1A）。英文小字 "AI ENGINEERING FROM SCRATCH" 放下面（VT323, #7A7A78）。

**适用场景**: App 图标、微信头像、favicon。在所有小尺寸场景下可简化为单个 3×3 方块矩阵（去掉文字）。

---

### 4.3 方向二：「三线蓝图」(Triple Blueprint)

**概念**: 三条平行的蓝色线段，长度递增——短、中、长——像施工蓝图上的三根标尺。最长的线末端是一个发光的节点。

**几何构成**:
```
━━━━━━━━ ●
━━━━━━
━━
```

- 三条线宽 3px，间距 8px，颜色均为蓝图蓝 500
- 最短线 = Phase 1-7（基础），中线 = Phase 8-14（核心），最长线 = Phase 15-20（前沿）
- 最末端的圆点（直径 8px）使用蓝图蓝 400 + 外发光，代表「多智能体集群」
- 左边的起点处可以叠加一个微小的光标符号 ▎

**文字组合**: 三条线在上，品牌名在下。整个 Logo 呈横向布局，适合公众号封面顶部水印。

**适用场景**: 横向封面、Banner、视频水印。不适合极小尺寸（三条线在 16×16 的 favicon 里会糊成一团）。

---

### 4.4 方向三：「源·启」(Source & Start)

**概念**: 将「AI」两个字母做几何重构——「A」是一个向上的三角形（代表从基础到顶点），「I」是一根竖线（代表工程落地的一贯性）。两个形状的交集处形成一个小的方形开口——「从零开始的零」。

**几何构成**:
```
  △       ← A: 向上的三角形（顶点 = 多智能体集群）
  ‖       ← I: 两根竖线（双轨制 = 手写 + 工程）
 └──┘     ← 底部入口: 方形打开（从零开始）
```

- A 的三角形：蓝图蓝 500 填充，顶点朝上
- I 的双竖线：蓝图蓝 300 和蓝图蓝 500 并置，代表「理解」和「实现」双轨
- 底部开口：透明/米白，象征「任何人都可以从这里进入」
- 整体几何感强，不需要弧线，全部用直线和直角

**文字组合**: 图形在上（正方形比例），中文品牌名在下。

**适用场景**: 这是最「像 Logo」的方向，适合作为主品牌标识。有足够的辨识度和几何简洁性，在微信小头像（160×160）里也能辨认。

---

### 4.5 推荐选择

| 场景 | 推荐方向 |
|------|---------|
| **主品牌 Logo**（第一优先级） | 方向三「源·启」——最具辨识度，适合所有尺寸 |
| **微信公众号头像** | 方向一「蓝图方阵」——在小尺寸（60×60圆形裁剪）下依然可辨 |
| **B站/知乎封面水印** | 方向二「三线蓝图」——横向舒展，与封面设计兼容 |
| **favicon / 小图标** | 方向一「蓝图方阵」简化版（仅 3×3 方块，无文字）|

> **建议首次落地**: 先出方向三的高清 SVG/AI 源文件（作为主 Logo），同步出方向一的简化版（作为头像和 favicon）。

## 6. 禁止使用规则

### 6.1 颜色禁忌

| ❌ 禁止 | ✅ 正确做法 |
|---------|------------|
| 蓝图蓝用在 `#FAFAF5` 背景上时加投影/描边 | 蓝图蓝在白/浅色背景上纯净使用，不加任何效果 |
| 将蓝图蓝渐变到其他非品牌色 | 渐变只用蓝图蓝 400 → 500 → 600 |
| 在任何严重警告场景使用蓝图蓝 | 警告/错误用琥珀 500 或赤红 500 |
| 正文使用 `#1A1A1A` 全黑 | 正文用 `#1A1A1A`（已经是 90% 黑，不过度） |
| 暗色主题用纯白 `#FFFFFF` 做正文 | 暗色主题正文用 `#E8E6DC`（暖白，不刺眼） |
| 同一页面出现超过 3 种非中性色 | 最多同时使用: 蓝图蓝 + 琥珀 + 翠绿（共 3 种） |

### 6.2 Logo 禁忌

| ❌ 禁止 | ✅ 正确做法 |
|---------|------------|
| 拉伸/压缩 Logo 改变宽高比 | 始终等比缩放，锁定宽高比 |
| 改变 Logo 颜色（尤其不要改成渐变色） | 只用品牌色: 蓝色版（#3553FF）、白色版（#FFFFFF）、黑色版（#1A1A1A） |
| 在复杂背景上直接放 Logo | 确保 Logo 周围有足够的安全空间（≥ Logo 高度的 50%） |
| 给 Logo 加阴影/描边/发光 | Logo 保持平面几何风格，不做任何立体效果 |
| Logo 内部元素拆分使用 | Logo 是一个整体，不可拆出三角形或方块单独用 |
| 旋转 Logo（除了 90°/180° 的倍数） | Logo 只能水平放置，不做旋转 |

### 6.3 字体禁忌

| ❌ 禁止 | ✅ 正确做法 |
|---------|------------|
| 标题使用衬线体（宋体/楷体）做标题 | 标题始终用无衬线体（PingFang SC / Microsoft YaHei） |
| 正文使用黑体（太粗，影响长文阅读） | 正文用 Regular 字重（400），不用 Bold（700） |
| 代码块使用非等宽字体 | 代码永远只用等宽字体栈 |
| 混用超过 3 种字体 | 一篇文章 ≤ 3 种字体: 标题+正文/代码/品牌英文 |
| VT323 用在中文字体上 | VT323 仅用于英文品牌名和 Phase 编号 |
| 行间距 < 1.5（中文密集阅读疲劳） | 行间距 1.8-2.0 |

### 6.4 排版禁忌

| ❌ 禁止 | ✅ 正确做法 |
|---------|------------|
| 封面标题超过 12 个字（信息过载） | 封面标题 ≤ 12 字（8-10 字最佳） |
| 同一视觉出现超过 3 个信息层级 | 严格控制: 标题（主）→ 副标题（辅）→ 标签（微） |
| 代码截图宽度超过 680px | 代码截图适配公众号 680px 内容区宽度 |
| 在微信文章中插入超过 3 张连续大图 | 每 300-500 字配一张图，图文交错 |
| 封面文字放在底部 10% 区域 | 底部 10% 可能在分享时被微信 UI 遮挡 |

### 6.5 平台特定禁忌

| 平台 | 禁止 |
|------|------|
| **微信公众号** | 不使用自定义背景色（微信会覆盖）；不使用 Web Font（不会加载） |
| **知乎** | 不使用公众号排版工具生成的内容（格式会炸）；数学公式必须用 LaTeX |
| **B站** | 封面不放太多文字（16:9 缩略图在列表页很小）；标题不加 emoji（影响搜索） |
| **小红书** | 图片不加微信二维码（平台会限流）；不加外部链接 |
| **掘金** | 不使用公众号风格的引导语（掘金社区很反感「关注公众号」这种话） |
