> 原文: [Autonomous Vulnerability Hunting with MCP](https://blog.zsec.uk/bullyingllms/)
> 作者: Andy Gill（@ZephrFish），安全研究员，前渗透测试专家
> 阅读时间: 约 12 分钟

## 一句话总结

安全研究员 Andy Gill 搭建了一套基于 Claude Code + MCP 的**自主漏洞挖掘系统**——8 个 MCP 服务、300+ 工具、5 台虚拟机协同工作，在不到三个月内挖出 2 个 Go 标准库 CVE、一个 OEM 软件 SYSTEM 权限 0day 链，以及多个 macOS 漏洞。本文是他对整套系统的完整拆解。

## 为什么选这篇

中文安全圈关于「AI + 漏洞挖掘」的讨论大多停留在 prompt 工程层面：「把二进制丢给 ChatGPT 让它分析」——然后就没了。而这篇文章是极少数**完整展示工程架构和验证管线**的深度分享。

Andy 不仅搭了系统，还做出了实际产出（有 CVE 编号那种），并且坦诚地聊了什么没做成、什么踩了坑、什么还在改进。这种「既秀肌肉又亮伤疤」的写法，在安全圈原创内容中相当稀缺。

另外——这篇文章的标题虽然是 _Bullying LLMs into submission_（欺负 LLM 让它老实干活），但 Andy 设计的**"幻觉回收站"验证管线**恰好是当前 Agent 工程中最实用的反幻觉模式之一。安全场景对误报的容忍度极低，这让他的架构选择对通用 Agent 开发者也很有参考价值。

## 核心观点

**观点一：不要相信 LLM 的输出——先用"幻觉回收站"关起来。** Andy 设计了一个反直觉的流程：所有发现默认标记为"幻觉"，必须通过四道验证关卡（PoC 编译→崩溃复现→可利用性→低权限触发）才能升级为"有效发现"。这套机制把误报率压到了接近零。

**观点二：知识复利比单次发现更重要。** 每次漏洞挖掘的结果——成功的、失败的、被防御机制挡回来的——全部进 RAG 索引。第 20 次挖掘的效率和精准度远高于第 1 次，因为系统"记得"哪些二进制有防护、哪些崩溃模式见过、哪些漏洞类型值得追。这就是知识的复利效应。

**观点三：用 ROI 驱动目标选择，而不是靠运气。** 系统跟踪了 100+ 漏洞奖励计划，按漏洞类别估算回报、按竞争激烈程度打折，算出每个目标的期望 ROI。结果：系统自动避开了 Chrome 内核这类"百万奖金但百人抢"的卷王目标，转而盯上了**装机量大但少有人看**的 OEM 管理软件。

**观点四：MCP 是 Agent 与工具之间的"通用插头"。** 8 个 MCP 服务覆盖了虚拟机管理、逆向工程、模糊测试、漏洞利用开发、调试器、知识检索、基础设施、报告生成——每个都是一个独立的 Python 进程，Claude Code 通过标准化的 `@mcp.tool()` 接口调用。不用复制粘贴终端输出，不用切窗口。这就是 MCP 在实战中的真实形态。

## 深度解读

### 一、架构一览：8 个 MCP，5 台虚拟机，300+ 工具

Andy 的实验室基于 Proxmox 虚拟化，5 台 VM 在隔离网段中运行：

| 虚拟机 | 系统 | 角色 |
|--------|------|------|
| hunt-win11 | Windows 11（最新补丁） | 主要攻击目标 |
| hunt-win11-n1 | Windows 11（N-1 补丁） | 补丁对比，找 Patch Tuesday 修了什么 |
| hunt-winserv | Server 2022 | RPC、服务、AD 攻击面 |
| hunt-kali | Kali Linux | Ghidra、radare2、pwndbg、angr |
| hunt-fuzz | Windows 11 | 专用模糊测试（WinAFL、Jackalope） |

8 个 MCP 服务覆盖整条漏洞挖掘链路：

- **Lab Controller** — SSH/WinRM 会话管理、虚拟机控制
- **Hunter** — 补丁对比、攻击面枚举、10 个 fuzzing 域、崩溃分类
- **RE Tools** — Ghidra、radare2、Frida 等逆向工具封装
- **Exploit Dev** — Shellcode 生成、堆喷射、PoC 组装
- **Debugger** — 持久化 WinDbg/GDB 会话
- **RAG** — 所有挖掘数据的语义搜索
- **Infra** — 按需扩展模糊测试虚拟机
- **Reporting** — 漏洞报告、赏金提交、CVE 申请

每个 MCP 服务都是**瘦 wrapper + 厚业务逻辑**：`@mcp.tool()` 装饰器只做参数解析和调用转发，真正的逻辑在独立的子模块里。这样业务代码可以独立测试、独立迭代。

### 二、幻觉回收站：为什么 Andy 认为这是整个系统最重要的设计

"Hallucination Bin（幻觉回收站）"是 Andy 自己起的名字，本质是一套**四关验证管线**：

1. **Gate 0：PoC 存在且能编译** —— 不是「看起来好像能触发」，是「写完能跑」
2. **Gate 1：在干净快照中复现崩溃** —— 排除环境噪声
3. **Gate 2：崩溃可利用** —— 不是空指针解引用或优雅退出
4. **Gate 3：标准用户权限触发** —— 不是 SYSTEM/admin 独占才能碰到的

只有四关全过，发现才会从 `hallucinations/` 目录提升到 `findings/`。

Andy 举了一个很诚实的例子：早期一次挖掘中，系统自动标记了 6 个"发现"，日志和解编译输出看起来都很有说服力。但经过动态分析人工审核——**6 个全是误报**。幻觉回收站在它们靠近最终报告之前全拦住了。

这套设计放到通用 Agent 开发场景中也很有启发：**不要让 Agent 自己审核自己**。把验证拆成客观、可执行的关卡，用外部工具和确定性规则把关，而不是依赖模型自评。

### 三、知识循环：每一次失败都在让下一次更聪明

这是 Andy 最满意也最有复利效应的设计。流程分为五步：

1. **Hunt** — 挖掘前先查知识库：「这类二进制以前崩溃过吗？什么技术有效？什么防御挡住了？」
2. **Collect** — 所有崩溃记录（10 个 fuzzing 域）全部入库
3. **Enrich** — 厂商安全公告、补丁对比、变体分析、赏金结果持续补充
4. **Learn** — 通过 FAISS 向量库 + sentence-transformer 自动索引
5. **Repeat** — 下一次挖掘带着更丰富的上下文启动

此外还有一个"已知防御数据库"——当目标被确认有 AM-PPL 防护、SxS 保护或严格签名验证时，该机制会被记录，后续该目标的优先级会**递减**。几次被 AM-PPL 挡回来后，系统就不再推荐这些目标了。

这才是真正的"越用越聪明"——不是靠更大的模型，而是靠**结构化的经验积累**。

### 四、ROI 驱动的目标选择：别跟一百个人抢同一个 bug

Andy 的赏金情报模块跟踪了 100+ 漏洞奖励计划，在选择目标之前先算一笔账：

> 期望 ROI = 保守赏金估计 / 估计挖掘时长 × 竞争调整系数

- DLL 劫持：约 8 小时
- 本地提权：约 20 小时  
- 远程代码执行：约 40 小时
- 内存破坏类（类型混淆/UAF）：约 80 小时

竞争越激烈，系数越低。热门 OS 厂商的系数只有 0.4——你找到了 bug，可能还有三个研究员比你早报。

结果就是：系统自然偏向**装机量大但少有人盯**的软件——OEM 管理工具、企业中间件、第三方系统工具。那枚 OEM 0day（下文会讲）就是这个排名策略的直接产物。

### 五、实战产出：两个月，两个 CVE，一枚 0day 链

**Go 标准库 CVE × 2：**

Andy 对 Go 的 `x/image` 包发起了语法引导的模糊测试，覆盖 21 个标准库包，总计约 8000 万次执行。两个高危成果：

- **CVE-2026-33809**：一个 8 字节的精巧 TIFF 文件，IFD 偏移指向 `0xFFFFFFFF`，导致 `buffer.fill()` 分配约 4GB 内存——OOM 杀死进程。8 字节就能触发。
- **CVE-2026-33812**：构造字体文件，GPOS 表的 class count 乘积不经验证直接传给内存分配，两个 uint16 最大值相乘 ≈ 8GiB——瞬间 OOM。

两个 CVE 的修复代码均已提交并纳入 Go 官方版本（Andy 本人提交了修复 PR，Go 维护团队审核后合入主分支）。受影响的下游包超过 945 个（原文作者估算）。

**OEM 软件 0day 链（Auth Bypass → SSRF → SYSTEM 代码执行）：**

这是一套四阶段攻击链，从标准用户到 SYSTEM：

1. **命名管道认证绕过** — 认证逻辑只在客户端，服务端完全不验
2. **WCF SSRF** — 一个 WCF 方法接受攻击者 URL 参数，没有权限检查，SYSTEM 服务乖乖发 HEAD + GET
3. **目录注入** — 伪造的"紧急更新"被系统接受为合法更新
4. **SYSTEM 二进制执行** — 最后一道防线是 Authenticode 签名，但 Andy 找到了一条 BYOVD 路径

这条链已提交给厂商并确认有效。Andy 没有完全公开 BYOVD 细节——负责任披露。

**macOS 发现 × 2：**

通过静态分析 + Frida 动态插桩，在一个 macOS 应用分发平台上挖到了浏览器历史窃取和生产环境私钥泄露两个问题。

Andy 特别提到一个教训：**静态分析找到的线索必须用动态分析验证**。Frida 跟进是让这两个发现从"需要更多信息"升级到"已分类"的关键步骤。

## 我的思考

这篇文章最让我印象深刻的反而不是那些 CVE 和 0day，而是 Andy 对自己系统的**诚实评价**。

他公开了 TokenBurn 的成本追踪工具，承认如果按 API 计费的话大约是 £5000/CVE，但 Max 订阅模式 + 知识复利让单位成本持续下降。他还坦诚：大部分挖掘活动不产生任何有效发现。"幻觉回收站的目录比有效发现目录大得多——这恰恰说明系统在正常工作。"

另一个值得注意的细节：Andy 的 RAG 不仅索引实战数据，还包含他**过去 15 年积累的 56 万条笔记**、5800+ Sigma 规则、1025 个精选 GitHub 仓库。这意味着系统的知识起点不只是"这一轮的发现"，而是一个安全研究员**整个职业生涯的脑外记忆**。这值得每个考虑用 Agent + RAG 做知识管理的人思考——你的"种子数据"是什么？质量够吗？

最后，Andy 在结尾写到未来的方向：训练自己的门控 delta 网络 + MoE transformer 模型，基于 Qwen 但重新调整权重以聚焦他自己的研究方向。这说明这套系统的最终目标不是"AI 取代研究员"，而是**让研究员的经验能以可训练的方式沉淀下来**。
