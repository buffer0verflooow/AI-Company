# 内容质检策略

> **版本**: v1.0
> **制定日期**: 2026-07-05

---

## 1. 为什么需要质检

本项目产出的文章涉及技术事实、CVE 编号、统计数据、链接引用。未经审核的内容可能包含：

- **事实错误**：CVE 编号不存在、版本号不准确、数据来源不可靠
- **断章取义**：对原文的解读偏离原意
- **幻觉注入**：AI 辅助写作时编造看似合理但不存在的数据
- **链接失效**：引用的 URL 404、重定向或内容变更
- **版权风险**：直接翻译段落而未标注引用

质检不是"不信任写作者"，而是**内容工程的必要环节**——正如软件工程中的 code review。

## 2. 质检角色

| 角色 | 职责 | 由谁担任 |
|------|------|----------|
| **事实核查员（Fact Checker）** | 验证所有可验证声明：CVE 编号、统计数据、技术细节、链接有效性 | 待指定 |
| **内容审校（Copy Editor）** | 检查文风一致性、可读性、中英文混排规范、错别字 | 待指定 |
| **主编终审（Editor-in-Chief）** | 最终把关：选题方向的战略一致性、不发布有争议/低质量内容 | 待指定 |

## 3. 审核流程

每篇文章在发布前必须经过三个关卡：

### Gate 1：事实核查（Fact Check）

执行人：事实核查员

检查清单：

- [ ] 所有 CVE 编号在 [NVD](https://nvd.nist.gov/) 或 [MITRE](https://cve.mitre.org/) 中可查到
- [ ] 所有 GitHub issue/PR 链接可访问且内容与引用一致
- [ ] 所有统计数据标注来源，非原文数据需额外标注推导方式
- [ ] 版本号、日期、金额等数字与源数据一致
- [ ] 所有外部链接（原文、延伸阅读）可正常打开
- [ ] 文中任何「原文未提及但文章写了」的内容，用 `[编者注]` 或脚注标明

### Gate 2：内容审校（Copy Review）

执行人：内容审校

检查清单：

- [ ] 标题吸引力与准确性的平衡（不标题党）
- [ ] 文章结构遵循项目模板（一句话总结 → 为什么选这篇 → 核心观点 → 深度解读 → 思考 → 延伸阅读）
- [ ] 「我的思考」部分有理有据，不与原文混淆
- [ ] 中英文混排规范（英文单词前后有空格、代码用等宽字体标记）
- [ ] 无错别字、语法错误
- [ ] 是否添加了原文未提及但读者会想知道的中文语境补充

### Gate 3：主编终审（Final Approval）

执行人：主编

检查清单：

- [ ] 选题与项目定位是否一致
- [ ] 原文是否仍然可访问（发布前最后检查一次）
- [ ] 无敏感/争议内容
- [ ] 封面图与文章内容匹配
- [ ] 发布平台（微信/知乎/小红书）适配版本已准备

## 4. 验证工具

| 工具 | 用途 |
|------|------|
| `curl -I <url>` | 验证链接可达性 |
| `curl -s "https://services.nvd.nist.gov/rest/json/cves/2.0?cveId=CVE-XXXX-XXXXX"` | 验证 CVE 编号 |
| `gh issue view <url>` / `curl <github api>` | 验证 GitHub issue/PR 状态 |
| `firecrawl scrape <url>` | 获取原文最新状态，对比引用内容 |

## 5. 应急流程

- **发布后发现事实错误**：立即在原文首段添加 `[更正]` 标记，说明错误内容和更正后内容
- **原文内容更新**：原文作者更新后，评估是否需要更新我们的解读，必要时发补充说明
- **链接失效**：检查 Internet Archive，如不可用则在原文位置添加 `[链接已失效]` 标记
