### 读二进制的问题

**静态分析**告诉你程序**能**做什么。把它放进反汇编器，跟踪交叉引用，你会得到全部可能行为的空间。这个空间巨大无比，其中大部分永远不会被执行，而且没有任何信息告诉你程序在凌晨3点决定回传数据时，实际走了哪条分支。

**动态分析**告诉你程序**实际做了**什么，这有用得多，但也难捕捉得多。挂上调试器，你获得精度，但同时也获得一个"停世界"的工作流：断点、检查、单步、继续、丢失位置、从头再来。这对于单个函数还行。但有趣的行为分散在四个线程、一个子进程和八秒你总是跳过不看的启动时间里时，这种方式就崩溃了。

这套工具包的存在就是为了弥合这一差距。观察整个运行过程，然后深入分析那十二条真正重要的指令。

### CallHook：它到底在调什么？

CallHook 注入到正在运行的进程中，按顺序记录它发起的调用及其参数。不只是 IAT 里的导入，也不只是沙箱恰好勾住的那么几个 API：在全单步模式下，它观察执行本身，因此动态解析的调用、内部辅助函数，以及任何通过指针到达的调用，都会和显而易见的 `CreateFile` 流量一起出现。

（附图：CallHook 跟踪一个 PowerShell 进程 — 实时调用表，包含时间、序列号、线程、深度、调用方和被调用方列，下方面板显示选中调用的参数，以指针值及十六进制/ASCII 转储形式展示。）

截图说明："CallHook 运行中追踪：一个 PowerShell 进程的 3,593 次调用，选中的调用参数以十六进制和 ASCII 形式转储。"

截图中几个细节比看起来更重要：

1. **RVA 偏移（从模块基址开始的字节偏移）** — 这是屏幕上最有用的数字：它直接将你定位到反汇编器中的调用站点，无需搜索。
2. **调用深度** — 快速分辨这是直接调用还是经过三层封装的间接调用。
3. **线程信息** — 看到跨线程的调用序列，模式就浮现出来了。
4. **开启加载器追踪** — 显示模块解析的实时过程，大量有趣行为隐藏在这里：侧加载、延迟导入和手动映射都会在此现身。
5. **随时暂停追踪** — 标记重要时刻，然后导出。

追踪结果可按函数、模块或参数内容搜索，并可保存。这能将一个行为问题转化为可 diff 的构件：捕获工作状态的追踪，再捕获失败状态的追踪，然后对比两者。

### TrueDiffing：什么变了？

Diffing 是逆向工程中杠杆率最高的技术，因为发布补丁的厂商已经准确告诉了你漏洞在哪里。难点从来不是概念本身，而在于程序重新编译后一切都会移动。地址偏移改变，函数被重排，编译器内联了新的内容，而字节级别的 diff 会把整个文件点亮。

TrueDiffing 在你实际思考的层次上工作。它解析两个文件，跨版本匹配函数，并将每个函数分类为：已修改、新增、删除或未变更。下面截图的计数器用一行信息概括了整个构建版本的变更：278 个已修改，1,947 个新增，1,671 个删除，共 3,896 个函数。

（附图：TrueDiffing 对比两个构建版本 — 左侧是按已修改/新增/删除分类的函数列表，右侧是选中函数的指令级 diff，显示操作码字节以及彩色标记的新增/删除指令。）

看一下那个 diff 的头部：`File Offset: 0x00000000 (Delta: +0xCF0)`，以及 `3,896 functions total` 的摘要。函数在两个版本间移动了超过 3KB，仍然被匹配并以指令对齐的方式呈现，操作码字节紧邻助记符显示，这样你能看到单靠反汇编文本看不出的编码变化。这种对齐就是全部关键：你比较的是代码本身，而不是偏移量。

它也不限于 Windows 二进制文件。截图中的构建版本是 **Linux ARM64 的 OpenSSL**，这正是实战中当目标设备不是笔记本时经常出现的那种目标。字符串标签页与函数标签页并列存在，原因相同：一个变更的字符串往往是指向变更功能的最快路径。

当指令列表不够时，切换到图形视图：

（附图：TrueDiffing 图形视图 — 两个控制流图并排显示，基本块按未变更/已修改/新增/删除着色，边标记为已走通/未走通路径。）

两个控制流图并排显示，每个基本块根据变更情况着色，每条边标记为已走通或未走通路径。这就是你发现边界检查悄然增加了分支，或循环多了一个出口的方式。悬停一个基本块，它会显示完整的反汇编；两个窗格可独立缩放和平移，这样你可以在两侧同时保持感兴趣的子图在视野内。完成后，导出报告交给当时不在你旁边的人。

最明显的用途是 1-day 分析，但它在日常工作中同样常有用场：比较你自己的构建在加混淆前后的差异，检查厂商在"小版本"更新中到底改了些什么，或者区分同一个恶意软件家族的两个样本。

### ExportFinder：它真正导入了什么？

CallHook 告诉你调用去了 `kernel32!SetEnvironmentVariableA`。然后你去 `kernel32.dll` 里找这个函数，但它不在那里。至少，在真正有意义的意义上不在。

（附图：ExportFinder 显示 kernel32.dll 的导出表 — 左侧是文件夹中的 DLL 列表，右侧是序数、RVA、名称和转发目标的表格，包括标记为转发器的条目。）

ExportFinder 读取导出表，告诉你真实现状：序数、RVA、名称，以及如果有转发目标的话一并展示。截图立即说明了问题：`kernel32!SetEnvironmentVariableA` 根本**没有 RVA**。它是一个**转发器**，目标为 `api-ms-win-core-processenvironment-l1-1-0.SetEnvironmentVariableA`，你要读的代码在一个完全不同的模块里。`kernel32!GetSystemInfo` 转发到了一个 `API set`，后者又根据宿主系统的不同解析到别处。

这不是冷知识。从中可以得出三件事：

1. **一半的导出表是转发器** — 传统上只查找 IAT 或单一导入表的分析，会错过整个执行路径。
2. **静态分析看不到转发链** — 反汇编器显示的调用可能是一个跳向另一个模块的跳板。
3. **API 集（API sets）增加了间接层** — 转发链可能系统而异。

ExportFinder 也是唯一一款**完全免费**的工具。没有许可证，没有试用计时器。下载后放在你其他工具的同一个文件夹里即可。

### NetHook：它发送了什么？

第四个问题，在二进制开始和外部通信时立刻出现。NetHook **在应用层**捕获、检查并重写进程的流量，通过 hook 应用程序用于收发数据的 API 调用。证书固定、自定义 TLS 栈和不支持代理的代码都变得无关紧要，因为你在数据到达网络之前就已经在读取缓冲区了。

（附图：NetHook 附加到一个 PowerShell 进程 — 捕获表显示 EncryptMessage、DecryptMessage 和 recv 调用，包含源和目标地址；旁边是数据包面板，以十六进制和 ASCII 显示纯文本 HTTP 请求，以及转发、修改或丢弃已保持数据包的控制按钮。）

从左往右看那个捕获表：`EncryptMessage` 出去的数据，`DecryptMessage` 和 `recv` 回来的数据，连接目标是 443 端口。右侧面板是同一个流量，以纯文本 HTTP 请求的形式显示，十六进制在一侧，ASCII 在另一侧，因为 hook 位于缓冲区上而非套接字上。从"捕获"模式切换到"拦截"模式后，数据包会被保持而非传递，这样你可以编辑它，然后选择转发、修改或丢弃 — 测试从此从观察变成了交互。

我们已经写过详细的文章了，这里不再重复：参阅《使用 NetHook 进行厚客户端渗透测试》（https://blog.truecyber.world/thick-client-pentesting-nethook）获取完整演练，或访问 NetHook 产品页面。

### 整合：一个实战案例

以下是将这些工具放入同一个工具箱后，一次真实会话的样子。假设你拿到一个更新程序二进制文件，它正在做一些不该做的事。

1. **CallHook** 查看它在运行时的调用 — 迅速发现它在一个可疑的偏移量下调用了 `WinHttpSendRequest`。
2. **ExportFinder** 解析实际目标 — 那个调用通过 `winhttp.dll` 链转发到了一个 API 集，最终解析到了 `httpapi.dll`。
3. **TrueDiffing** 将此版本与前一版本的更新程序对比 — 结果发现两条指令的变化：一个硬编码的 URL 被替换了。
4. **NetHook** 确认它发送的内容，以明文呈现 — 你拿到完整的故事：哪条代码路径、为什么改变、以及什么离开了这台机器。

每一步只花了几分钟，并且产出了一个可以交给其他人的构件。整个过程不需要坐在断点上祈祷正确的线程撞上来。

## 四、安全探索关联分析

### 战略价值

1. **工具形态参考**：TrueCyber 的"一工具一问题"设计哲学值得借鉴 — 小而精确的工具比大而全的套件在实际工作中更有实用价值。每个工具聚焦一个特定的逆向问题域（调用追踪、二进制差异、导出表分析、流量拦截），工具之间通过数据流自然衔接。

2. **完整的逆向工作流**：四款工具覆盖了从"程序运行时在做什么"（CallHook）到"它与什么通信"（NetHook），从"新旧版本差异"（TrueDiffing）到"导入解析"（ExportFinder）的完整链路。这是一个可以借鉴的逆向工程闭环方法论。

3. **ExportFinder 的免费策略**：ExportFinder 完全免费但功能专一精准，起到了漏斗入口的作用 — 用户使用 ExportFinder 后自然会考虑购买其他三款工具。这个"入口工具免费、核心工具付费"的模式值得考虑。

### 技术关注点

- CallHook 的全单步（single-step）模式实现细节未公开，但提到观察"执行本身"，暗示可能使用了硬件断点或单步标志（TF）机制
- TrueDiffing 的函数匹配算法跨 3KB+ 偏移仍能精确对齐，暗示基于函数指纹（指令序列哈希 / 控制流图同构）而非地址匹配
- NetHook 在应用层而非网络层工作，hook API 调用以捕获明文数据，这种方法对加密流量特别有效
