## 1. 结论摘要

ZeroPath 的漏洞挖掘方法论是「深度程序分析 + 对抗性 AI Agent 验证」的混合架构:
用 tree-sitter AST + 调用图做代码导航底座, 静态规则/S CA/威胁建模生成候选, 再用
ToT + ReAct + MCTSr 三种 AI 推理框架做多路径探索与实用性验证, 最后用 LLM 作为
"win function" 决定攻击假设是否达到可利用阈值。方法论价值等级: **HIGH** —
其「候选生成宽、验证收紧」的两段式设计与本蜂群 P5 验证门同构, 且其 53% 发现集中在
授权缺陷 (IDOR/越权) 的事实印证了 LLM 系工具在传统 SAST 模式匹配失效处的真实增益。
该文章是产品营销文 (附 CTA 表单), 所有统计数字为厂商自述, 未经独立基准验证, 引用需标注来源。

### E3 方法论管线 (事实, 原文 Stage 1-4)
1. **应用识别**: AI agent 探查仓库内的应用 (应对 monorepo/微服务), 识别目录边界, 生成应用描述/元数据 (认证流程、技术栈)。
2. **AST 生成与索引**: tree-sitter 转 AST (统一节点命名), 构建**调用图** (函数调用关系图), 作为漏洞分析时的导航结构。
3. **图增强**: 识别外部可达端点, 为节点附加属性 (请求路径、HTTP 方法、认证/授权机制), 识别中间件与安全控制在整个流程中的位置。
4. **发现与验证**: 漏洞分三类 — 常规 (SQLi/XXE/XSS/CSRF/密钥泄露/SSRF)、业务逻辑 (价格操纵、优惠券滥用、工作流绕过、缺限速)、认证授权 (IDOR/缺失功能级访问控制/会话管理缺陷)。

### E4 候选生成手段 (事实, 原文列举)
- 静态规则: 大量脆弱模式规则 + 语义搜索。
- 威胁建模: LLM 生成攻击场景, 通过对代码的严格调查验证。
- SCA: 监控依赖已知漏洞, 并判断其外部可利用性。
- 密钥扫描 + 有效性验证 (非只扫存在性)。

### E5 AI 推理框架 (事实, 原文 + 引用论文)
- **ToT** (Tree-of-Thoughts, arXiv:2305.10601): 多路径推理、中间步骤评估、结果排序 — 用于复杂场景探索。
- **ReAct** 改编 (arXiv:2210.03629): 结构化工具使用 + 显式动作论证 — 提高调查过程严谨性。
- **MCTSr** (Monte Carlo Tree Self-Refine, 基于 arXiv:2406.07394, 上海AI实验室/复旦 IMO 求解工作): 在攻击向量决策树上做蒙特卡洛探索 + 自精炼, 宣称"更高效的探索 + 更少误报"。
- **关键机制 (win function)**: 由 LLM 实现, 评估攻击假设的成功概率与严重度; 按漏洞类型 (SSTI/SQLi/XSS/业务逻辑) 配备不同验证 agent, 综合前序阶段信息与所有让攻击不切实际的缓解控制; 超过"实用性阈值"才进入补丁生成阶段。
- 原文明确承认: 这些 bug 大多简单, 安全研究员代码审查或部分扫描器即可发现; 传统 SAST 的问题是规则匹配漏掉不符合已知模式的复杂漏洞 (业务逻辑/坏认证/来自依赖的非传统 sink) 且误报率高。LLM 的价值在消歧: 不报测试代码、不报仅管理员可触达的 CLI、不报 sink 实际不可控、不报存在缓解控制 (如输入被限制为合法 UUID) 的注入。

## 5. 修复建议 (方法论转化落地, 按优先级)

1. **[HIGH] 把"LLM 实用性阈值"引入蜂群候选过滤**: 在 scanner 产出候选后、exploiter 投入前, 增加一个轻量 agent 检查四类消歧 (测试代码/管理员专用路径/不可控 sink/存在缓解控制), 直接砍掉 P5 阶段的无效验证开销。这是本文最可操作的单点。
2. **[HIGH] 攻击面地图升级为"图增强"模型**: 对目标仓库/APK 建立 端点→方法→认证属性 三层标注, 替换纯路径枚举; 对接 AI 安全攻击面地图定位 (公司产品方向)。
3. **[MEDIUM] 业务逻辑目标采用 ToT+ReAct 骨架**: 蜂群 P2/P3 处理业务逻辑类目标时, 显式要求多路径推理 + 工具调用论证, 避免单线深挖。
4. **[MEDIUM] SCA 增加可利用性判定**: 依赖漏洞不只看 CVE 存在, 加一步"该漏洞是否从外部可达"验证 (对应原文 SCA 做法)。
5. **[LOW] 密钥扫描升级有效性验证**: 对发现的密钥做真实可用性探测 (如 API key 调一次只读接口), 减少误报。
6. **[LOW] 跟进 4 篇 write-up 与完整 CVE 表**: 建议后续任务抓取 zeropath.com/blog 下 4 篇技术分析, 提取具体复现链做证据沉淀。
