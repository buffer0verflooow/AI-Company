## 1. 坐标系：攻击面全景（唯一真理源）

**所有选题、实验品、工具、服务必须能在八面上定位。定位不了的，不进 backlog。**

| 攻击面 | 危害链 | 公司现有实证/资产 | 对应检测器（B 线候选） | 优先级 |
|---|---|---|---|---|
| 供应链面 | AI 网关劫持→密钥提款机 | LLM Heist + LiteLLM 文章（08-09/08-11） | 网关流量完整性监控 | CRITICAL |
| 身份面 | 凭证共享 69%→越权/横向 | 方向评估 E4-E6（107 企业调研） | Agent 身份/凭证审计器 | CRITICAL |
| 输入面 | Prompt 注入→工具越权→RCE | 蜂群实测经验（~45% 发现占比） | 注入检测/分类器 | HIGH |
| 工具面 | 过度授权→合法工具非预期使用 | 自家审计 F3（tool_policy 零强制） | MCP 工具权限审计 | HIGH |
| 模型面 | 静默降级→旧漏洞复活 | Fable 5 文章 + issue #66728（08-11） | **模型降级监控（已立项）** | MEDIUM·差异化 |
| 记忆面 | 记忆投毒→决策污染 | PoisonedRAG 实测 90% 操控 | 记忆完整性检测 | MEDIUM·差异化 |
| 通信面 | Agent 间通信无加密认证 | 自家审计 M2（signal_board 级联信任） | 通信面审计 | MEDIUM |
| 输出面 | 输出未消毒→XSS/SQLi | 方向评估 E1 | 输出消毒检查器 | MEDIUM |

**坐标系锚点 = 自家蜂群**：蜂群是唯一同时具备「检测工具」与「被测对象」双重身份的资产。F1-F8/M1/M2 的实证链（全行级证据、可复现）是任何外部框架引用替代不了的一手数据，也是技术路线最短验证路径。

## 2. 能力体系（五维）

| 维 | 能力 | 现状 | 建设方向 |
|---|---|---|---|
| 攻 | 蜂群 AI 红队 | MARBLE 100/100；H1 173+ 发现 | 攻防对：每攻击面一个可复现攻击实验 |
| 防 | 检测器矩阵 | 模型降级监控（立项未开发） | 按 §1 表格逐面建设，季度 1 个 |
| 验 | 评测方法论 | P5 验证门（判据化/双轮复核） | 升维为「Agent 安全评测方法论」，服务前身 |
| 知 | 知识体系 | KB + wiki + 情报 + 雷达 | 攻击面条目与检测器条目互链（知识-能力映射） |

**专业化定义**：五维闭环（攻→防→验→知→传）每个攻击面走一遍 = 一个完整能力单元。能力单元叠加 = 专业化护城河（厂商能写综述，写不了行级实证）。

## 3. 技术路线（四阶段）

### P0 坐标系 ✅ 已完成
- 交付：ai-security-attack-surface-report.md（八面 + 优先级 + F1-F8/M1/M2 实证）
- 意义：一切后续工作的定位基准

### P1 自家加固闭环（当前阶段）
- 目标：修复 F1-F8 高危项 + M1/M2 缺口，把蜂群自身变成「安全基线达标」的 Agent 基础设施
- 产出：修复（能力）+ 修复过程实录（文章/素材）+ KB 条目（知识）
- 依据：自家审计报告 `~/workspace/research/swarm-knowledge/reports/security-audit-2026-08-11.md`（A19 complete-task 无鉴权 HIGH 等 P1/P2 未修项）
- 验收：A19/A16/A14/A17 关闭；M1/M2 注入链标记

### P2 检测器矩阵（主线，季度 1 个）
- 顺序 = §1 优先级 × 差异化：
  1. 模型降级监控（已立项，差异化位 P5，需求证据最实）→ 挂模型面
  2. 记忆投毒检测（差异化位，空库更易写入的反直觉点）→ 挂记忆面
  3. 网关流量完整性监控（CRITICAL 面，但需谨慎——避免与 LiteLLM 生态撞车）→ 挂供应链面
- 每个检测器 = 纯 stdlib 脚本 + 模拟端点测试 + 24h 零误报验收 + 事件留痕（复用 product-incubation-pipeline.md 的验收/回滚模板）

### P3 评测产品化（D→A→C 渐进，2026-08-16 用户确认"以产品为视角"）

**方法论内核（六模块）**：维度定义（攻击面八面）→ 用例库（注入/越狱/投毒/降级样本）→ 执行器（蜂群 233-agent 并行）→ 指标（通过率/防御覆盖率/准出线）→ 报告（发现→证据→影响→修复）→ 迭代（情报→新用例）。一句话：**"蜂群作为执行器 + 攻击面地图作为维度 + P5 验证作为质量门" = 可重复的 AI 安全评测引擎**。公司已有 80% 零件，缺的是组装成产品。

**对标（2026-08 快照）**：Garak（NVIDIA 开源扫描器）/ PyRIT（微软红队框架）/ HarmBench·AgentDojo（评测基准）/ CyberSecEval（Meta）——海外大厂已占位；**国内独立 AI 安全评测产品空白 = 空窗**。

**产品化路径（不一步到位，形态按序推进）**：
- **D 评测报告（内容，现在）**：用蜂群评测公开 Agent 框架/产品，发布评测报告系列。零合规负担、产线现成，验证"市场要不要 AI 安全评测内容"，同时跑通方法论、攒报告样张
- **A 开源工具（中期）**：报告有反响后，把方法论固化为开源 CLI（蜂群评测引擎），对标 Garak 但 Agent 时代。解决 career-gap 差距5（无开源硬通货），一鱼两吃（声望+跳槽作品集）
- **C 评测服务（远期期权）**：等付费信号（enterprise-gap 阶段2 触发条件），用 D+A 攒的样张接单。护栏：不启动直到主体/资质/责任三件套就位

**明确不做**：B 基准集（学术红海，现阶段耗时不成比例）；C 服务现在不启动。

**处女作选题（D 形态）**：蜂群评测开源 Agent 框架（LangGraph / AutoGen / CrewAI 安全性对比）——接"以产品为视角"，报告即方法论落地的第一份样张。

**对齐 OWASP ASI 2026 判据**（ASI01-ASI10），产出 = 评测报告样张（服务前身，企业化阶段 2 交付物原型）。

### P4 变现（触发条件驱动，不提前）
- 触发信号：付费咨询/求购持续出现（enterprise-gap-analysis 六支撑阶段 2 门槛）
- 路径：评测工具开源（声望）→ 评测服务（签单）→ 培训（现金流）
- 护栏：不启动服务直到主体/资质/责任三件套就位

## 5. 结构性问题（为什么之前"看到什么是什么"）

1. **无坐标系**：8 份文档各自成立，但没有一份回答"这件事在攻击面地图的哪个位置"。选题靠情报热点，实验品靠单文章信号（模型降级监控是拍板选的，不是从八面推导的——方向对，但推导路径没写出来）。
2. **蜂群双重身份未利用**：蜂群既是工具又是靶场，这个锚点没有成为技术路线的出发点。
3. **攻防未成对**：文章偏攻（实测），产品偏防（监控），中间缺"攻→防"的推导链。
4. **能力与知识脱钩**：KB 存发现但检测器不引用 KB，文章选题不引用坐标系。

**本文的修正**：坐标系立起来后，任何新信号先定位（哪个面？哪个攻击链？），定位不了就归档，不进 backlog。
