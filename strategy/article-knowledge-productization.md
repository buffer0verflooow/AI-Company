# 已发布文章知识沉淀 + 产品孵化管线

> 问题: 已发布文章是否融入公司知识库?文章方向如何孵化产品?
> 核查结论(2026-08-11): **没有入库** — wiki/ 仅 3 个文件, 零篇文章; 已发文章只留 evidence/source.md 素材, 无结构化沉淀, 无 swarm: capture 标记, 蜂群 Agent 读不到。

---

## 1. 知识库闭环缺口(现状)

| 环节 | 现状 | 缺口 |
|---|---|---|
| 文章产出 | evidence/ 存素材、草稿箱存稿、发布 | ✅ |
| 发布记录 | 选题池 ✅ 标记 | ✅ 但只到"标题+日期"粒度 |
| 结构化沉淀 | 无 | ❌ 无 wiki 笔记、无提炼洞察 |
| 知识库入库 | 无 swarm: capture 标记 | ❌ 蜂群读不到 |
| 产品孵化 | 战略文档(企业化六支撑) | ❌ 未与文章方向挂钩 |

**根因**: 产线设计时把"公众号稿件"划为不入库对象(obsidian-swarm-kb-bridge 铁律 1),但这条铁律没区分"营销稿"和"技术洞察"。已发布文章中含大量可复用技术结论、攻击模式、产品信号,属于知识资产。

## 3. 落地方案 A: 已发布文章 → 知识库

**3.1 回写 wiki(人读资产)**
每篇已发布技术文章生成 wiki 笔记: 技术结论 + 攻击模式 + 数字证据 + 与赛道的关联。命名: `wiki/articles/<slug>.md`, 带 `swarm: capture` 标记。

**3.2 知识提取入库(Agent 记忆)**
- 文章笔记打 `swarm: capture` + `swarm_tags`(按赛道 A/B/C/D)
- 跑 `automation/capture_from_obsidian.py` → 蜂群 KB 可检索
- 每篇文章 5 条以内的"可复用知识条目": 攻击模式/防御缺口/产品信号

**3.3 产品信号提取(孵化输入)**
每篇文章末尾加"产品信号"区块, 明确: 这篇文章证明了什么需求/什么技术缺口 → 对应什么潜在产品。喂给市场雷达与选题池。

**3.4 回写机制自动化**
在文章产线 QA Gate 之后加"知识沉淀步骤"(skill company-operations 更新):
- 发布确认 → 自动生成 wiki 笔记骨架 → 人工/Agent 提炼 5 条知识 + 产品信号 → capture 入库

## 4. 落地方案 B: 文章方向 → 产品孵化管线

**4.1 现有基础(已就位)**
- 四赛道: A 攻防实战 / B EDR对抗 / C Agent安全治理 / D 变现向
- 战略部: 内容→评测→服务→培训 变现路径; 六支撑企业化路径
- 市场雷达 + 情报采集: 选题池从市场信号来

**4.2 缺口: 从"文章主题"到"产品方向"的转化机制**
新增 `strategy/product-incubation-pipeline.md`:
1. **信号收集**: 采集/文章/市场雷达 → 技术缺口 + 需求信号
2. **信号验证**: 文章阅读/互动/转发反馈 + 蜂群调研验证需求真实性
3. **方向收敛**: 每季度从信号中选出 1-2 个可实验方向
4. **实验品**: 工具/规则/数据集/报告(评测工具的定位, 无合规负担)
5. **付费验证**: 免费→付费 转化信号出现后, 才进入企业化阶段(已有三阶段路径)
