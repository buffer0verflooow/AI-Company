# 跳槽能力补全计划：AI 安全工程师/研究员（主）+ 红队（次）

> 编制：公司主 Agent
> 目标岗位：AI 安全工程师 / AI 安全研究员（主攻），红队/渗透测试（次选）
> 依据：公司 Wiki 实绩 + HackerOne hunt 记录 + 技能树盘点

## 1. 现状画像（证据驱动）

| 维度 | 实绩 | 证据 |
|------|------|------|
| 攻防广度 | 极强 | HackerOne 4 campaign、红队技能树 58 方法论、EDR 绕过实作 |
| AI Agent 架构 | 独特优势 | 自建 233-agent 蜂群系统、swarm-knowledge DIKW、多模型编排 |
| LLM 安全知识 | 有体系 | llm-security skill（OWASP LLM Top 10 v2.0 + Agentic AI）、30 篇深度文章 |
| 工程能力 | 扎实 | Python 全栈自动化、Android/Kotlin + TFLite、SQLite 体系 |
| 内容输出 | 强 | 30 篇文章 4354 阅读，硬核数据风，能把技术讲清楚 |

## 2. 目标岗位要求（2026 市场标准）vs 现状差距

### 差距 1【最致命】：无可证明的 LLM 漏洞实战案例 ❌
- **现状**：所有 H1 发现（Unico 173 条等）全是传统 Web/移动/云/API 漏洞；**零**真实产品 LLM 漏洞（prompt injection / Agent 工具滥用 / 模型供应链）挖掘记录
- **岗位要求**：AI 安全岗面试第一问就是"你挖过/防护过什么 AI 系统的洞"，无案例 = 无入场券
- **补法**：P0

### 差距 2【独特但未转化】：Agent 架构理解未安全化 ⚠️
- **现状**：能设计 233-agent 系统，但从未以**攻击者视角**审计过 Agent 系统（prompt injection 进 agent、工具权限逃逸、MCP 安全、知识库投毒）
- **机会**：全球同时具备"深度攻防 + 能自己搭 Agent 系统"的人极少——这是最大差异化，但需要变成可讲的案例
- **补法**：P0（自家蜂群当靶场）

### 差距 3【变现闭环断裂】：173 发现 0 收入 ❌
- **现状**：Unico 173 条 = 117 INFO（67%）+ 17 HIGH + 24 MEDIUM + 14 LOW，只提交 3 份报告
- **根因**：数量型挖掘（蜂群批量扫描堆 INFO）≠ 价值型挖掘（精筛 HIGH + 高质量报告 + 被接受）
- **岗位影响**：面试官看"被接受了几单、解决了什么问题"，不看"扫描出多少条"
- **补法**：P0（复盘 + 重提 + 报告质量门）

### 差距 4【AI 工程深度】：无产品级 LLM 应用经验 ⚠️
- **现状**：会调 Agent 框架、懂架构，但没写过产品级 RAG/Agent 应用、没审过推理服务（vLLM/Triton）代码
- **岗位要求**：AI 安全岗要能读懂模型服务代码、理解训练/推理管线攻击面
- **补法**：P1

### 差距 5【研究硬通货】：无 CVE/开源工具/公开研究项目 ❌
- **现状**：有文章无代码作品；技能树广但无可引用的公开项目
- **岗位要求**：研究员岗看 CVE、GitHub 项目、论文/博客影响力
- **补法**：P1（开源 Agent 安全审计工具）

### 差距 6【企业语言】：合规/流程认知 ⚠️
- **现状**：技术强，企业安全治理语言（等保/ISO 27001/SDL/红队演练交付）未见记录
- **补法**：P2（进企业前的低成本补齐）

## 3. 补全计划（8 周，P0 优先）

### P0 - 第 1-3 周：建立可证明的 AI 安全案例（面试入场券）
1. **自家蜂群安全审计**（独有武器）：对 swarm-knowledge 系统做攻击者视角审计
   - prompt injection 进 agent（工具输出投毒、系统提示注入）
   - 工具权限逃逸（executor 越权、沙箱绕过）
   - 知识库投毒（swarm_knowledge.db 注入恶意知识）
   - MCP/工具链攻击面
   → 产出：《自建 233-agent 系统的安全审计》案例 + 修复清单
2. **LLM 漏洞真实挖掘**：H1/众测平台选 2-3 个有 bounty 的 AI 产品目标（LLM 应用/Agent 产品），跑 LLM 安全专项（OWASP LLM Top 10 + Agentic 攻击面）
3. **Unico 变现复盘**：筛 173 条中可提交的 HIGH → P5 验证 → 按 H1 报告标准重写 → 目标 2-3 单被接受（解决 0 收入，直接可写进简历）

### P1 - 第 4-6 周：作品集 + 知识补齐
4. **开源工具**：把蜂群审计方法论做成可复用的 Agent 安全审计工具（GitHub）
5. **文章系列**（公司产线）：每补一块知识产一篇 → 内容资产 = 面试谈资
   - 《自建 Agent 系统的攻防审计》（蜂群案例）
   - 《Agentic AI 攻击面全景》（OWASP Agentic AI 落地解读）
   - 《LLM 供应链攻击：恶意模型/数据集投毒》
6. **AI 工程补课**：RAG/Agent 框架生产化 + 读 vLLM/Triton 推理服务代码（能审计 AI 基础设施）

### P2 - 第 7-8 周：面试收口
7. **简历重构**：30 篇文章选 5 篇代表作、173 发现 → 3 个精选案例、蜂群审计案例、开源工具
8. **岗位需求验证**：用智联招聘抓取"AI 安全工程师"真实 JD（上轮已验证可抓），核对差距清单
9. **红队次方向**：如走红队，补证书（CRTO/OSCP 或国内 CISP-PTE）+ 企业红队交付报告语言

## 4. 与公司资源的协同

- **文章产线**：每块知识补齐自动产出一篇文章（学习 + 谈资双收）
- **蜂群**：当靶场（审计） + 当工具（挖掘）
- **P5 验证门**：报告质量保障
- **市场雷达 jobs 通道**：挂智联招聘抓 AI 安全岗位 JD → 需求侧验证（对接 2026-08-11 招聘平台抓取可行性调研）

## 5. 关键成功指标

- [ ] 1 个完整的自家 Agent 系统安全审计案例（含修复）
- [ ] ≥2 个真实 LLM 漏洞提交，≥1 单被接受（打破 0 收入）
- [ ] 1 个开源 AI 安全工具（GitHub）
- [ ] 3 篇 AI 安全深度文章（产线）
- [ ] 智联抓取的真实 JD 差距验证表
