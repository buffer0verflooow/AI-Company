## 收敛决策(2026-08-12): 首选 = 模型降级监控

**收敛到「模型降级监控」** — 理由(按优先级):

1. **需求证据最实**: 降级不是理论——Fable 5 静默降级 Opus 4.8 有推文实证 + 官方 issue #66728 佐证; 攻击者只需找到触发降级的开关, 不需要新漏洞(可复用知识条目 #1)。
2. **差异化最强**: "检测静默降级"市场上几乎没有成熟工具(对比网关检测有 LiteLLM 生态/商业 WAF 竞争者, EDR 评估有成熟厂商), 是空白点。
3. **贴合主方向**: 用户跳槽主攻 AI 安全工程师——模型路由/降级监控是 AI 基础设施安全的直接案例, 比 EDR 评估(红队次级方向)支撑度更高。
4. **实验品形态清晰且低合规负担**: 巡检脚本, 周期性对比请求/响应模型一致性, 无外部目标、无攻击动作, 不需要 EDR 环境等重资源。
5. **变现路径可延伸**: 工具实验 → AI 安全评测服务(记忆安全/降级维度), 与"评测工具的定位"一致。

**弃选信号的处置**:
- AI 网关安全检测 → **保留为下一季度候选**(第二优先级), 信号仍有效, 等降级监控验证后接续。
- EDR 绕过评估 → **降级为素材库**(BYO EDR 文章的知识沉淀已够), 暂不发实验品; 若红队方向需求明确再激活。

## 实验品定义: model-downgrade-monitor

- **名称**: 模型降级巡检脚本(`model-downgrade-monitor`)
- **功能**: 周期性(如每小时)向配置的 LLM 端点发探针请求, 比对请求指定的模型 vs 响应实际模型; 检测到静默降级(响应模型 ≠ 请求模型 或响应 model 字段缺失/异常)时告警并记录事件
- **形态**: 纯 stdlib Python 脚本 + cron 化, 无外部依赖; 探针用最小 token 请求(如 "hi")控制成本
- **边界**: 只读探测, 不发攻击载荷, 不触碰生产密钥(凭证从环境变量读)

## 验收标准(Outcomes rubric)

**MVP 达标(判定实验品成立)**:
1. [ ] 能检测出真实降级: 用模拟降级端点(配置一个代理故意改响应 model 字段)测试, 告警准确率 100%(无漏报)
2. [ ] 正常端点零误报: 对正常 LLM 端点跑 24h, 误报 = 0
3. [ ] 事件留痕: 每次降级事件写入 JSONL(时间/请求模型/响应模型/请求上下文), 可回溯
4. [ ] 成本可控: 探针 24h token 消耗 < 5 万 tokens(约 0.01-0.05 元量级, 具体按价目表核)

**延展验收(进入付费验证阶段的门槛)**:
5. [ ] 真实端点检测到至少 1 次降级事件(或通过红队测试证明可发现)
6. [ ] 有 1 个外部使用者(公司之外的人/团队)表示愿意用
7. [ ] 可输出一份"降级检测报告"样张(评测服务雏形)

## 回滚条件

出现以下任一情况, 停止实验品投入, 回滚为信号保留:
1. **误报不可控**: 24h 误报 > 3 次且无法通过阈值/白名单修复 → 停用告警, 保留采集
2. **成本失控**: 探针 token 消耗超预算 5 倍且无优化路径 → 降低频率或停
3. **需求证伪**: 30 天内无任何外部兴趣(无试用/无反馈/无互动), 且蜂群调研也确认需求弱 → 归档信号
4. **方向变更**: 用户职业/公司方向调整, 优先级重排后此信号不再 top-2 → 归档

回滚动作: 停 cron、归档运行产物到 `strategy/archive/`、在本文档状态栏更新结论(不删信号, 保留素材)。
