# 编译来源与定位

Lupin（@0xLupin，Depi 创始人、红队研究员）X 观点长文《security researchers are doomed.》，2026-08-12 发布，2 天内编译为公众号文章并推送草稿箱（run a9931f31，已 P5 独立核验）。

## 核心论点

1. **机器自动化掉的是「对已知目标类别，执行已知技术」**——安全研究里可被吃掉的只是执行层。
2. **还没被自动化的三件事**：决定看什么（目标选择）、理解没人写下来的信任边界、发明昨天还不存在的漏洞类别。
3. **「你被自动化是发生在身后，不是身前」**：工具吃掉你发表的工作 = 证明贡献真实，然后去找下一个。类别命名本身就是贡献（作者 DEF CON 33 命名 npx used-confusion 后，第三方工具 npxconfuse 自动化了检测）。
4. **预言历史 0:3**：Morton（电灯）、Preece（电话）、Krugman（互联网 ≤ 传真机）说「机器不会成功」全错；Metcalfe 最懂机器也错。而说「要付出真实代价、需治理过渡」的人（Ricardo《论机器》1821、卢德分子、Big Six 的 Powers）每次都对。
5. **两种论证的倒置**：对安全研究员说「你没用了」不是第二种论证（治理警告），而是第一种论证（能力预测）的倒置——零证据、不干这行、对干这行的人做自信预测。
6. **结论：工作不安全，位置安全**——「找到当前工具还看不见的东西」这个位置两百年没有反例，它一直在移动。Powers 乔装混进印刷展销会「去看那台机器」是全文最聪明的动作。

## 可复用知识条目（≤5）

1. 攻击模式：**npx used-confusion**（供应链）——把已知模式（bin 混淆）应用到新技术（npx）即构成新漏洞类别；命名类别 = 贡献，自动化检测 = 贡献被验证。参考 landh.tech 博客（RONI CARTA | LUPIN）。
2. 防御缺口：AI 安全产品方向——「工具自动化吃掉发表的工作」在 AI 安全领域是常态，产品的差异化价值在「还没人命名过的类别」。
3. 行业判断框架：区分「能力预测」（说机器不会成功，历史 0:3 全错）与「治理警告」（说过渡有代价，历史全对）——评估 AI 对职业影响时用第二类框架。
4. 观点文编译样板：忠实编译 + 来源标注 + 无法核验处显式标注（Drake 所指、Powers 轶事细节）+ 编译手记与正文观点分离。

## 产品信号

「工具自动化 vs 安全研究者的价值位置」是 AI 安全职业焦虑的核心议题，与公司 AI 安全产品方向（模型降级监控、网关检测）互补：产品价值定位可复用「吃掉已发表工作 ≠ 取代位置」的论证。
